# 逻辑原型

一个自包含的 HTML 文件，也就是一份**可分享的演示**：任何人点按钮就能驱动状态模型。适用于问题关乎**业务逻辑、状态迁移或数据形状**的场合——这类东西在纸上看合理，真推演几个案例才会觉出不对。

因为它只是一个文件、不需要安装任何东西，你可以直接交给不写代码的人（设计师、产品经理、业务专家），让他们自己感受这套模型。所以它说的是他们的语言，不是代码的语言。

## 何时用这个分支

- 「我不确定这个状态机处理 X 之后再 Y 的边界情况时对不对」
- 「这个数据模型真能表达……的情形吗」
- 「我想在动手写之前先摸清 API 该长什么样」
- 凡是**想按按钮、看状态变化**的场合

如果问题是「界面该长什么样」，走错分支了，用 [UI.md](UI.md)。

## 流程

### 1. 明确要回答的问题

动手写代码之前，写清要原型的是哪个状态模型、要回答什么问题。一段话即可，放在演示顶部**可见的说明**里，不要只写进注释。答错问题的原型纯属浪费，所以问题必须写明确，便于日后核对——无论用户此刻在旁观看，还是过些时候回来看。

### 2. 把逻辑隔离成可移植模块

把真正回答问题的逻辑放在单个 `<script>` 块里，写成一个小而纯的模块，日后能被整体取出、放进真实代码库。外层页面是一次性的，这个模块不是。

形态取决于问题：

- **纯 reducer**：`(state, action) => state`。动作是离散事件、状态是单一值时适用
- **状态机**：显式状态与迁移。「此刻哪些动作合法」本身就是问题的一部分时适用
- **一组纯函数**：作用于朴素数据类型之上。没有隐含的当前状态、只有变换时适用
- **带清晰方法面的类或模块**：逻辑确实需要持有跨调用的内部状态时适用

按**最适合问题**的形态选，而不是按最容易接到页面上的形态选。保持纯净：不碰 DOM，不用 `document`，不让按钮处理器伸进模块内部。页面调用它，反方向不流动。这正是原型在自身寿终之后仍有价值的原因：问题答完，验证过的 reducer、状态机或函数组可以原样搬进真实模块。

### 3. 写出那份可分享的 HTML 文件

一个文件，纯 HTML/CSS/JS：不用框架，不用打包器，不用服务器，所有内容内联，双击即可打开，邮件转发也不会散架。任何人都应该能打开就跑。

写给不写代码的人看。所有标签都用**领域语言**，不用代码语言：按钮与状态读起来像业务，而不像 reducer。用平实的话解释正在发生什么。

自上而下，用清晰的层级排布：

1. **标题与一句话说明**：这个演示让你探索什么（即第 1 步的问题）
2. **当前状态**：完整的相关状态，渲染成可读的面板（带标签的字段，而不是裸 JSON），每次点击后重绘，使变化可见。有助于非开发者跟上的地方，点明刚刚变了什么
3. **自由操作按钮**：每个动作一个按钮，始终可用，任何人都能按任意顺序试。每次点击派发对应动作并重绘状态
4. **引导式场景**：一组**场景**，一个场景一个标签页。每个标签页里有该场景的简短说明（它设置了什么局面、要看什么），下面列出该场景要依次按的**按钮**。每一步都是真按钮：点击即执行该动作并前进到下一步。启动某个场景时回到已知的初始状态，使每次运行都一样

场景要挑那些不好在纸面上推理的别扭情形：正常路径、棘手的边界情况、以及一次本该非法的尝试。

保持美观但克制：排版干净，留白充足，只用一个强调色。不做动画，不要花活——任何与状态和按钮争夺注意力的东西都不加。

### 4. 交给用户

把文件发给他们，或直接替他们打开。他们得空就会点开场景与自由操作；有意思的时刻通常是他们说「等一下，这不该允许」或「咦，我以为 X 会不一样」——那是**想法本身**的缺陷，也正是这一步的目的。他们想加新动作或新场景就加，原型是会长大的。

### 5. 留存结论与原型

原型的自问自答完成后，先记下结论，再按 [SKILL](SKILL.md) 所述留存原型。逻辑分支的对应关系是：验证过的 reducer、状态机或函数组搬进真实模块（决策被吸收）；HTML 外壳随之进入一次性分支，使原型作为一手资料留存——它只是一个自包含的文件，在那里重新跑起来毫不费力。

## 反模式

- **不要加测试。** 需要测试的原型已经不是原型
- **不要接真实数据库。** 用内存存储，除非问题专门关于持久化
- **不要泛化。** 不写「万一以后要支持 X」，原型只回答一个问题
- **不要把逻辑与页面混在一起。** 纯模块一旦引用 DOM、`document` 或按钮处理器，就不再可移植。页面只应是纯模块之上的一层薄壳
- **不要引入框架、打包器或服务器。** 一个文件、双击即可打开；上了 React 或 dev server，「可分享」就没了
- **不要把 HTML 外壳带进生产。** 页面是为在浏览器里手动点击而优化的，值得留下的是它背后的逻辑模块
