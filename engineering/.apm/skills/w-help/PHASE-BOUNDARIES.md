# 阶段边界

**阶段（phase）** 是会话里的一块工作：拷问、实现、验收。这个定义故意模糊：当你想「这块算是做完了」的时候，一个阶段就结束了。

**阶段边界** 是两个阶段之间的空档，也是这个决策唯一该做的地方。阶段中途没有决策可做：要么继续，要么把剩下的工作拆给 subagent。阶段中途 compact 会让 agent 丢掉线索。

## 五个选项

| 选项 | 它做什么 |
| --- | --- |
| **继续** | 留在会话里，完全不切换上下文 |
| **`/clear`** | 清空上下文窗口，从零开始 |
| **`/handoff`** | 写一份可携带的 markdown，在任何地方用它开新会话 |
| **Subagent** | 把任务送到它自己的上下文窗口，拿回一份报告 |
| **`/compact`** | 压缩当前上下文，用摘要开一个新会话 |

## 决策树

在边界上从上往下走，第一个「是」即为答案。

**1. 这次会话能继续吗？** 两件事让答案是「能」：下一阶段把这一阶段当**primary source**用；或者你还剩足够的 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k token）容纳下一阶段。拷问 → 实现是标准的「能」：实现要的是推理的原文，不是摘要。继续不花成本也不丢东西，所以先把它排除掉再谈别的。

**2. 这份上下文和接下来要做的事无关吗？** 这次会话里的所有东西（探索、决策、死胡同）都可丢弃吗？如果是，**`/clear`**。它是棋盘上最便宜的一步：不花时间，整窗归还。`/clear` 也不是终局：旧会话仍然可以恢复。

这一步判断错的代价是单向的。清掉一份**相关**的上下文，你就丢掉了「为什么这么做」，事后读多少遍 diff 都换不回来。

**3. 需要交接吗？** `/handoff` 的范围很窄。只有这几种情况才需要：

- 换到**新的 harness**（Claude → Codex）；
- 换到**新目录**或换仓库；
- 把工作交给**同事**；
- 或者**阶段中途**发现一个支线任务，想分叉出去又不打乱手上这件事。

这张清单就是全部条件。`/handoff` 买到的是**可携带性**：一份能带走的文件。没有东西要带走，就不需要它。

**4. 这个任务能 AFK 跑吗？** 范围够紧、不需要你在旁边指挥吗？那就派给 **subagent**，这次会话原封不动。自动评审是标准场景：agent 读 diff 出报告，全程不需要你。

**5. 否则，`/compact`。** 上下文相关、同一个 harness、同一个目录，而你必须持续参与其中：决策树就落到这里，而且经常落在这里。给它一句指令（`/compact 我们接下来要验收这块`），让摘要留住下一阶段需要的东西。

`/compact` 是**默认选项，不是第一反应**。它排在底部，因为上面四个问题要么更便宜、要么更精确。人们一上来就用它时的失效模式是：新会话对某个被摘要压平的决策，自信地判断错了。

## primary source 与 secondary source

除**继续**之外的每一步，都把**primary source**换成了**secondary source**：真实发生的那次会话，被一份摘要取代。这笔交易形状始终相同：

| 来源 | 信息 | 噪音 | 后续腾挪空间 |
| --- | --- | --- | --- |
| primary source（继续） | 完整 | 多 | 小 |
| secondary source（`/compact`、`/handoff`） | 有损 | 少 | 大 |

这就是为什么第一个问题先问「能不能继续」。只有在留下的代价高于丢掉的信息时，才值得付这份有损的账。

## 这些都是判断题

这五个问题都不客观：每个都含判断成分，同一条边界在不同日子可能有两个答案。它们的价值在于**按顺序**问，而且要在边界上问，而不是在活儿干到一半时问。
