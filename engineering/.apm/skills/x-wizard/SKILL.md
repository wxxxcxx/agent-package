# 向导（Wizard）

**向导**是一个 bash 脚本，带着人一步步走完一套手工流程——手工做很烦，每次给 AI 解释一遍也烦。它会自动打开每个 URL、明确说清点哪里复制什么、把值收下来写进该去的地方（`.env`、GitHub secrets）、每个环节都确认一次、并显示还剩几步。它可以用来配置第三方服务、跑一次性迁移、或把项目从一个状态搬到另一个状态。

好用的那层体验已经由 [template.sh](template.sh) 解决：阶段进度、确认关卡、跨平台打开 URL（含 WSL）、隐藏输入敏感值、幂等的 `.env` 写入、`gh secret`/`gh variable` 写入、收尾汇总。**你只需要划定流程范围、编写各个阶段。** `STAGES` 标记以上的库在每个向导里都完全一样——这种一致性就是重点，**永远不要手改它**。

向导默认是一次性的：为跑一次而生，存到临时目录或 `scripts/`，活干完就删。只有用户希望把这条安装路径长期留在仓库里时，才提交它。

## 流程

### 1. 划定流程范围

把用户必须亲手做的每一步、沿途要收集的每个值都列出来。**先读仓库，别空口就问**：

- 配置类：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置、`.github/workflows/*`（每处 `secrets.*` / `vars.*` 引用都是一个必须产出的值）。
- 迁移或切换类：当前状态、目标状态，以及两者之间不可逆的动作。

然后把阶段顺序和每个阶段产出的值列给用户确认：他们可以增、删、调整顺序。

**完成标准：** 每个阶段都按顺序命名，并且对每个要收集的值，你都清楚：(a) 人从哪里拿到它，(b) 它写到哪里（`.env`、GitHub secret、两者都写、或哪里都不写——有些阶段只是纯动作），(c) 它是否敏感（需要隐藏输入）。

### 2. 画出每个阶段的路径

对每个阶段，写清楚人要走的确切路径：打开哪个 URL、在里面做什么、值显示在哪里、填进哪个变量。例如："控制台 → Developers → API keys → Reveal test key → 复制"。

**凡是你不确定当前界面长什么样、或命令到底是什么的地方，就明说，去问用户或查文档——绝不编造可能不存在的步骤。**

**完成标准：** 每个阶段都能追踪到具体指令，陌生人照着能做。

### 3. 编写向导

把 `template.sh` 复制到目标路径。用每个步骤一个 `stage` 替换示例阶段，按依赖顺序排。只用库里的辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设成你实际写的阶段数。

按模板设的标准来：要值之前先打开 URL；敏感值一律用 `ask_secret`；每个要落盘的值都用 `write_env`；只有 CI 真正需要的值才 `set_secret`；任何不可逆动作之前 `confirm`。每个 `stage` 会清屏，只显示当前这一步——一个阶段只干一件事，别让人需要的信息被滚走。**不要碰标记以上的库。**

### 4. 验证并交付

- `bash -n <脚本>`；有 `shellcheck` 就跑一遍。
- `chmod +x <脚本>`。
- **不要自己端到端跑**——它会打开浏览器、卡在等人输入。改成静态走查：第 1 步列出的每个值都被收集、并落到第 1 步说的位置；每个 `set_secret` 的名字都与 CI 里的 `secrets.*` 完全对应。
- 告诉用户怎么运行。如果这是可复用的安装路径，就提交它，并在 README 里链接过去，让下一个人跑脚本而不是问 AI。
