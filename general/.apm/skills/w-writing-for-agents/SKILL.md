凡是写给 agent 读的文档——skill、`AGENTS.md` / `CLAUDE.md`、由指针指向的文档——都按这一套写。打包形式不同，写法相同：同样的杠杆让它们变得可预测，因为 agent 每次跑的是同一套**过程**，而不是产出同样的内容。

如果你写的是一份 skill，另读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，那里讲 frontmatter、调用方式的选择、以及路由型 skill。

## 上下文指针

**上下文指针**是留在 agent 上下文里的一个引用，它指向某份上下文之外的资料，并编码了"什么条件下该去取它"。skill 的 description 是一个指针；`AGENTS.md` 里点名某份文档的一行，是同一种东西。**决定 agent 何时、以及多可靠地去取资料的，是指针的措辞，不是它的目标。** 一个必须要用到的目标，配了一句软弱的指针，就是**方差 bug**：先把措辞改利，改不动才把内容内联进来。

指针干两件事：说明这份资料是什么；列出应该触发它的**分支**（分支 = 文档处理的一种独立情形，不同运行会走不同路径）。**每条常驻指针的每个字，每一轮都要付费**，所以它比正文更该被狠心裁剪：

- **把领头词前置**：指针就是它发挥触发作用的地方。
- **一个分支一个触发词。** 同一分支的同义词，等于把一条分支写了两遍——合并掉，只留真正不同的分支。
- **删掉正文已经承载的身份信息。**

## 两种负载

你加的每份文档、每个指针，都在花两种预算之一：

- **上下文负载**：常驻材料对 agent 窗口的占用——`AGENTS.md` 的一行、一个 skill 的 description、任何每轮都在上下文里的东西，不管触发与否都在烧 token 和注意力。
- **认知负载**：压在**人**身上的成本——有哪些文档、什么时候该拿哪个。**人就是索引。** 它不是要极力压缩的成本，而是人的主动性的代价：该用人判断的地方花它，不该用的地方去掉。

只能通过指针抵达的材料，免掉了上下文负载，代价是指针自身那一行；**完全没有指针的材料，全部压在认知负载上。**

## 信息层级

文档由两类内容构成：**步骤**（agent 按序执行的动作）和**参考**（定义、规则、事实，按需查阅）。两者可以自由混排：全是步骤（一份菜谱）、全是参考（一套评审规则、这份文档）、或两者都有。核心决策是每一块放在**信息层级**的哪一档——按 agent 需要的即时程度排序：

1. **文件内步骤**是主层级：agent 按顺序做什么。
2. **文件内参考**按需查阅。常常是一组合法的平级条目（一套评审规则同处一档），这是好安排，不是坏味道。
3. **外置参考**被推到独立文件，靠上下文指针抵达，只在指针触发时加载。范围从同目录的兄弟文件，一直到任何位置、任何文档都能指向的完全外部资料。

**往下推得太少，顶部就会臃肿；推得太多，又会藏掉 agent 真正需要的东西。** 这个张力就是全部决策。

**渐进披露**是沿着层级往下挪（挪出主文件、放到指针后面），让顶部保持可读。它主要不是省 token 的优化，而是**保护层级**的手段。**分支是判断该不该外置的最干净的检验**：每一条分支都需要的内容内联，只有部分分支会碰到的内容推到指针后面。当一份文档既有步骤又有本该外置的参考时，参考会把步骤埋掉，让"注意到步骤"变成掷硬币——这不只是可读性问题，更是在放大结果的波动。

**就近聚合**是文件内的配套原则：层级决定一块内容放在**多深**，就近聚合决定它落位之后**旁边放什么**。一个概念的定义、规则、注意事项要放在同一标题下，而不是散落各处，这样读到一处就带出邻居。检验标准：文档读起来应该像"给 agent 写的文档"。聚合的读起来像，散落的读起来不像。（这不同于重复：重复是同一含义写在两处；散落是同一含义被拆成很多碎片。）

**臃肿**是这一层的失效模式：文档就是太长了，哪怕每一行都是活的、唯一的。注意力被摊薄，而每多一行，就多一行要维持其相关性。解药仍是层级：把参考藏到指针后，按分支或时序拆分，让每条路径只携带自己需要的东西。

## 步骤与完成标准

每个步骤都以一条**完成标准**结束——它告诉 agent 工作已完成。两个属性让它成为杠杆：

- **清晰度**：agent 分得清"完成"和"未完成"吗？模糊的边界（"达成理解"）会招来**过早完成**：活还没干完就收工，注意力滑向"显得做完了"。前方还看得见的步骤（**完成后的步骤**）提供拉力，标准的清晰度就是阻力。防守顺序：**先把边界改利**（局部、便宜）；只有当它确实无法精确、且你观察到抢工现象时，才用拆分时序的方式把后续步骤藏起来。**隐藏只在真实的上下文边界上有效**（交接或派发 subagent；内联调用不会把后续步骤移出上下文，什么也没清掉）。
- **要求强度**：它要求多少功夫。"每个被改的模型都要交代清楚"会逼出细致的工作，而"给一份变更清单"不会。要求强度驱动**实打实的查证功夫**（agent 在工作中挖掘的部分，隐含在措辞里，而不是写成独立步骤），而且它不局限于步骤："每条规则都应用到了"约束的是一堆平级参考，正如"每一步都做完了"约束的是一段序列——这也是为什么纯参考型文档仍然可以带一条穷尽性门槛。

最强的完成标准，既**可检查**又**穷尽**。

## 什么时候该拆

把一份文档拆成两份，要花掉两种负载之一，所以只有当切口值这个价时才拆：

- **按序列拆**：一段步骤里，后面的步骤会诱使 agent 抢工当前这一步，就切开。把后续步骤藏起来，会促使 agent 在当前任务上投入更多查证功夫。反过来要小心：合并序列会把每一步的后续暴露给它之后的内容，招来过早完成。
- **按调用方式拆**（skill 专属）：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 领头词

**领头词**是模型预训练里已经存在的一个压缩概念，agent 在跑这份文档时就靠它思考（_lesson_、_fog of war_、_tracer bullets_）。它以 token 的形式反复出现，从不写成句子，从而积累出一份分布式定义，用最少的 token 锚住一整片行为区域——办法是调用模型已有的先验。自己造词也行，但要定义清楚；**造词不调用任何先验**：预训练词免费给你的东西，你得用自己的定义 token 付账。优先找现成的词。

它锚两次。在正文里锚**执行**：这个词一出现，agent 每次都取用同一套行为；在平级参考里，它把注意力聚焦到某一类要寻找的东西上。在指针里锚**调用**：当同一个词同时出现在你的 prompt、文档和代码库里，agent 会把这份共享语言与该资料关联起来，更可靠地去取它。

主动去寻找用领头词重构的机会。一个三元组在三个地方各写一遍，一个指针用一整句话去指一个概念——每一处都是等着塌缩成一个 token 的段落：

- "快速、确定、低开销" → _tight_（一个 _tight_ 循环）。
- "一个你信得过的循环" → _red_，把模糊的门槛变成二值可观测状态（这个循环对 bug 变红，或者不变红）。

你赢两次：token 更少，而且给 agent 一个更锋利的、可以挂住思考的钩子。**默认假设每份文档里都藏着可以被领头词取代的重述**，去找。

**否定**是这个杠杆旁边的失效模式：用禁止来引导，会把被禁的行为拖进上下文，让它**更**可得而不是更不可得。_别想大象_，脑子里全是大象；否定是一个弱修饰，会被强激活的概念盖过去，于是禁令有一半读起来像"去做这件事"。**要正面提示**：直接陈述目标行为（"写一行注释"），让被禁的那个说法压根不出现。禁令只有在它是无法正面表述的硬护栏时才配存在；即便那样，也要配上正面目标，让注意力落在该做什么上。

## 裁剪

- 每个含义只留**单一真相来源**：一个权威位置，改行为只需改一处。**重复**（同一含义出现在多处）既费维护又费 token，还会把该含义在层级上的显要程度抬过它的真实档位。（这是领头词的意外反面：领头词是故意重复一个 token，从不重复含义。）
- **环境**同样是信息的来源（`package.json` 的脚本、配置文件、目录结构、`--help` 输出），**复述环境的文档只是一份缓存**：查询结果的副本，只有查询本身昂贵时才值这份负载。缓存那些 agent 靠"看"找不到的东西：没写下来的约定、某个选择背后的原因、任何配置都不肯承认的坑。一个文件、一条命令就能查到的，交给环境，它不会过期。
- 逐行检查**相关性**：这行还跟文档要做的事有关吗？失相关有两种：从来不相关（纯说明，或本该外置的分支），或者它描述的行为/世界变了而它没跟上。文档越短越容易保持相关。没有裁剪纪律，默认结局是**沉积**：一层层过时内容堆下来——因为加东西感觉安全、删东西感觉有风险——直到必须层层深挖，才找得到还有效的内容。
- 逐条排查**空转指令**：模型本来就默认会遵守的指令，付费说了等于没说。检验标准（它相对默认行为有没有改变行为？）是**相对模型**的，不是相对读者：两个人对某句是不是空转有分歧，其实是对默认行为有分歧——解决办法是跑一遍文档，不是辩论。一句话没通过，就整句删掉，而不是从里面抠字。这个检验也用来给领头词打分：一个弱到打不过默认行为的词（agent 本来就比较细致了，你再说"要细致"）就是空转，修法是换更狠的词（_不留情面_），不是换技巧。
