## 它做什么

`grill-me` 拿一个**还没成形的想法**，访谈你，直到你能对它下决心。开始不必有一份想清楚的计划，因为这场 session 就是为了产出它。它按 **round** 提问。每个 round 是整个 **frontier**：所有前置条件你已经落定的问题。所以它永远不会问你一个依赖尚未听到的回答的问题。

它是 **stateless** 的：不写文件，不留下工作区。唯一的结果是那个想法在你脑子里变得更清楚。

## 什么时候用它

你手打 `/grill-me` 调用；agent 不会自己取用。开在**新对话**里，不要接在 agent 已经写好的计划上面。

一旦有个值得当真的想法（一个功能、一个产品方向、一个商业判断、一篇稿子）就用它，而且要在想清楚它牵涉什么之前。含糊不是等待的理由，session 存在的目的就是去掉含糊。如果你已经能精确说明这件事，就不需要 grill。

三个 grilling skill 选哪个，看你面前是什么：

- **任何东西、任何地方。** 用 grill-me。不需要仓库，不写文件，主题也不必是代码。
- **有一个代码库要对齐。** 用 grill-with-docs。同一场访谈，但它是 stateful 的：读你的代码，把学到的东西写进 `GLOSSARY.md` 和 ADR。
- **大到一次 session 装不下。** 用 wayfinder。它把这件事画成地图，在里面跑 grilling。

把 plan mode 关掉。plan mode 会催 agent 赶紧交一份计划，而你要它继续提问。

## 这是一场对话，不是一场考试

问题由 skill 问，范围由**你**掌握。这一点常被忽略。它决定了一场 session 是把想法变成决策，还是产出自信的废话。

失败模式是**被动**：四十个问题一路「同意、同意、同意」，最后拿出一份 agent 写的、你点过头的计划。它感觉有产出，因为很长。但你什么都没决定，结果的确定性比它看起来的低。

主动意味着掌舵。问题不够细，就顶回去；范围跑偏了，就说；不知道就答「不知道」，并且当真。这个 skill 帮工程师，不替代工程师。结果的质量取决于你回答的质量，不取决于问题的数量。

相反的错也真实存在，但少见：在访谈里待太久，永远到不了代码。

## 能 grill 的和不能 grill 的

有些问题谈一谈就有答案。有些不能，再怎么 grill 也到不了。

「用一个长表单还是三页？」「这个交互该是什么手感？」属于**不能 grill** 的。你得先有个东西可以反应，才答得出来。碰上这类，停掉 grilling，用 prototype 做一个丢弃版，看过之后再回来，一行话就能答。

硬要用谈话解决不能 grill 的问题，session 就会变长：agent 反复换说法，你反复猜，范围跟着不确定一起膨胀。

## 它在正常工作时

- 你有不同意的地方。一场你从不反驳的 session，是一场你本来不需要的 session。
- 问题分几个 round 到达，而不是长时间一题一题来；后面的 round 明显接着你前面说的话。
- 你最后停在一个没想到的地方，因为某个问题让你看见了一个你一直在做、却没察觉的决策。
- 结束时，你能向不在场的人解释每一个选择。

## 常见问题

**大概多少个问题？怎么知道结束了？**

数 round，不数问题。四十六个问题、四个 round，是普通的一场。frontier 空了就结束：每个分支都走过，没有留下未说出口的假设。

**它问了我两百个问题，哪里出错了？**

通常是范围太大。让 agent 先把活拆小，再逐块 grill。特别长的 session 还会滑进 **dumb zone**：context window 已经太满，问题开始变差。

**能不能改回一次一题？**

可以。在你的全局 `CLAUDE.md` 里加：

```
When grilling, ask one question at a time.
```

**我真的不知道答案怎么办？**

说出来。「不知道」是有效回答；答不出的问题，通常说明该去 prototype，而不是硬猜。

**写 spec 之前要开新 session 吗？**

不用。这场 session 的价值就是你刚建立起来的 context。把同一段对话直接交给 to-spec。

**model 重要吗？**

比多数 skill 更重要。grilling 依赖 model 自己对系统如何崩坏的认知，所以用你最好的那个。实施多半跟着 context 走，那里用便宜的 model 也行。

## 它的位置

grill-me 是**可随身携带的独立件，任何地方、任何主题都能跑**。因为 stateless，所以 portable：不需要仓库、工作区或配置，也不假设这个想法与软件有关。有人用它做商业判断、写东西、决定下一步：凡是独自想不清楚的事。

与 grill-with-docs 的差别只有可携带性。那个 skill 跑同一场访谈，但要读代码库来对齐，并把学到的东西记成 `GLOSSARY.md` 和 ADR。两者底下都用 grilling。grill-me 是不留状态的、面向用户的入口。

如果 grill 的东西最后确实是软件，可以把同一段对话交给 to-spec，接着走构建流程（这是个选项，不是这个 skill 的目的）。不确定该走哪条流程时，由 ask-matt 分流。
