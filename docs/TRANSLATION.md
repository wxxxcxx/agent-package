# 译文规范

适用范围：本仓库所有 `SKILL.md` 正文及其引用的 `.md`。英文原文不存于仓库，需要时用 `mattpocock.lock` 中记录的 commit 取回。

## 唯一的目标

**没读过原文的中文读者，能独立读懂，并且读到的意思和原文一致。**

其余各条都是为了达成这一条。任何规则与它冲突，以它为准。译文读着顺、但让读者以为原文说了另一件事，比读着生硬更糟——生硬会被发现，误读不会。

## 落笔之前

1. **先读懂。** 用自己的话把这一段复述一遍。复述不出来，说明还没读懂；此时照着单词换词，产出的必然是生硬的东西。
2. **分清楚这一段在讲什么。** 是定义、是步骤、是取舍、还是警告？文体对了，句子才立得住。

## 词怎么处理

3. **跟概念走，不跟单词走。** 同一个英文词在不同段落里可能承担不同的概念，中文应随概念变化，不必逐处对应同一个中文词。**不要建立「英文词 → 中文词」的固定对照表**：那种表会把一个词的多种用法压成一种，看似统一，实则窄化。

4. **判据是「读者能不能从字面理解」。** 能，就按字面写；不能，就把动作说出来。英文惯于把一个复杂的偏正短语当名词用，中文照搬会变成读者猜不透的堆叠；这时写成一个短句，交代清楚「做什么、结果是什么」。

5. **意译必须核对边界。** 换掉一个词之后，问自己三句：比原词范围窄了吗？宽了吗？同一概念在别处还是这个说法吗？窄化最隐蔽——它读起来毫不违和，却悄悄丢掉了原文的一部分。

6. **英文术语保留原词**（spec、ticket、seam、adapter、commit、subagent 等），首次出现用一句中文讲清它指什么，此后直接用原词。不另造译名，也不给同一概念换着说法——术语表的职责是让同一个东西永远叫同一个名字。

7. **不改的东西**：代码块、命令、路径、变量名、frontmatter、产品名。存在 `GLOSSARY.md` 时，采用其中说法。

## 句子怎么写

8. **书面、克制、动词承担语义。** 写「执行 X」，不写「X 的执行」。

9. **清除英文骨架。** 「……的参考」「允许你」「的情况下」「对于……来说」「进行／加以／予以／被……所……」这类句式，是英文句法套着中文汉字，改写成中文的说法。

10. **服从中文的语序。** 英文的前提从句在句首时，中文可以后置或拆句；一个句子塞三个从句，就拆成三句；一句之内「的」不超过两个。

11. **第二人称从简。** 原文的 you 多数可省。不用口语、俚语、语气词；可用「须、应、不得」等书面情态词，但一句之内不叠加。

12. **标点**：中文全角；英文术语与中文之间留一个空格；冒号优先于破折号；列表项以动词或名词开头，行尾不加句号。

## 收笔之前

13. **正向读一遍**：遮住英文，中文单独读得通吗？用词是中文技术写作里会出现的吗？

14. **反向核一遍**：只看中文，能否复原英文那一段的意思？有没有多出原文没有的断言，有没有漏掉原文的限定、条件、例外？

15. **对照上一版**：与既有译文逐段比，确认信息没有丢，也没有为了通顺而删掉难译的部分。

## 不译的内容

`.sh` 脚本、`CREDITS.md` 之类的致谢文件。脚本里的注释保持英文，改动容易在复制粘贴时出错。
