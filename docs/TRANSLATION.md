# 译文规范

适用范围：本仓库所有 `SKILL.md` 正文。英文原文不存于仓库，需要时用 `mattpocock.lock` 中记录的 commit 取回。

## 基本方针

**保留既有译文的语域：书面、规范、克制。只清除翻译腔，不改写成口语。**

翻译腔不是「中文不够土」，而是句子骨架仍是英文的。判断方法只有一条：遮住英文原文，这段中文是否仍能独立成立、语序是否自然。读得通但不顺，属于翻译腔；读得顺却丢了信息，属于过度改写。

修订幅度：**轻度**。以现有译文为底稿，逐句比对英文原文，只改句式与用词，不改结构、不删信息、不重排章节。已经通顺的段落不动。

## 必须清除的翻译腔

| 翻译腔 | 改为 |
| --- | --- |
| 这份文档是关于……的参考 | 本文说明…… |
| 它是……的参考 | 它是……的依据，供查阅 |
| 它允许你…… | 可以……，或用它…… |
| 你应该在……时使用它 | 在……时使用 |
| 这是很重要的 | 此点关键，或直接删 |
| 通过使用 X，你可以 Y | 使用 X 即可 Y |
| 为了……的目的 | 为了……，删去「的目的」 |
| 在……的情况下 | 在……时，或若…… |
| 对于……来说 | 对……，或改写主语 |
| 一个……的……的…… | 拆为两句 |
| 值得注意的是 | 直接陈述；确需强调写「注意」 |
| 此外、另外、同时（句首衔接） | 多数情况直接删 |
| 我们可以看到 | 删 |
| 进行、加以、予以 + 名词 | 直接用动词 |
| 被……所…… | 改主动，或省去被动标记 |

## 禁止直译式复合名词

英文习惯把多个名词与形容词压进一个偏正短语（`tracer-bullet vertical slices`），逐词对译会得到「曳光弹式的纵向切片」这种谁也读不懂的堆叠。中文里拆成一个短句，把动作说出来。

| 不采用 | 采用 |
| --- | --- |
| 曳光弹式的纵向切片 | 只打通一条窄而完整的路径，做完即可独立验证 |
| 可深化的机会 | 值得重构的地方 |
| 渐进披露的指针层 | 先给一层摘要，细节放在指针后面按需展开 |

规则：一个偏正短语里名词不超过两个；英文的隐喻（曳光弹、深模块、迷雾）不直接译成中文名词使用，只在首次出现时用一句话解释它指什么。

## 句法要求

- 动词承担语义。写「执行 X」，不写「X 的执行」。
- 英文的前提从句置于句首时，中文可后置或拆句，不必保留原顺序。
- 一句之内「的」字不超过两个，超过则拆句。
- 第二人称从简。原文的 "you" 多可省略，非必要不写「你」。
- 不用口语、俚语、网络用语与语气词：「就很」「挺」「搞」「弄」「其实吧」。
- 可用「须、应、不得、予以」等书面情态词，一句之内不叠加。
- 破折号作插入语，每千字不超过两次；英文 em dash 多对应中文冒号或直接断句。

## 术语处理

保留英文原词，不另造中文译名。这些词是检索关键词，译成中文反而查不到。

| 词 | 首次出现时补一句 |
| --- | --- |
| seam | 接缝：外部可观察行为、又无须深入内部的边界 |
| spec | 规格：明确「要做什么」的文档 |
| ticket | 工单：可被单独领取的工作单元 |
| tracer bullet | 曳光弹：先贯通一条最小可用路径，再逐步加厚 |
| ADR | 架构决策记录 |
| smart zone | 模型仍能保持推理质量的上下文区间 |
| subagent | 子代理 |

规则：

- 首次出现写「中文解释（english）」，此后只用英文。
- 代码块、命令、路径、变量名、frontmatter 一律不改。
- 存在 `GLOSSARY.md` 时采用其中说法，不另创新词。

## 标点与排版

- 中文全角标点；英文术语与中文之间留一个空格。
- 冒号优先于破折号。
- 列表项以动词或名词开头，长度尽量一致，行尾不加句号。
- 标题不使用「关于……」「……的介绍」。

## 自检清单

- [ ] 遮住英文原文，中文单独读得通
- [ ] 有无「进行 / 加以 / 予以 / 的情况下 / 对于……来说 / 的参考」
- [ ] 有无「的」字连用三处
- [ ] 有无口语词与语气词
- [ ] 英文术语首次出现是否附一句解释
- [ ] 代码块、路径、命令是否原样
- [ ] 与上一版逐段比对，信息无遗漏
